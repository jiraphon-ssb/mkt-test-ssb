# หน้าแคมเปญ (Campaigns) — Design Spec

วันที่ 12 ก.ย. 2026 · สถานะ: รอพี่อาร์ตอนุมัติก่อนลงมือ · ต่อจากรายงาน "ระบบล่าสุดของ Codex + ข้อเสนอหน้าแคมเปญ"

## 1. เป้าหมาย

หน้า `/mkt/campaigns` ตอบคำถามของ **คนยิงแอด** (พี่ทัชดูสรุปที่ Overview):
> ในแบรนด์/แพลตฟอร์มที่เลือก **แคมเปญไหน**กินเงิน · ตัวไหนทำผล · ตัวไหนเริ่มล้า · ควร **สเกล / ตรวจแก้ / หยุด / รอข้อมูล / ติด Gate** ตัวไหน — พร้อมเหตุผลและตัวเลขที่ตรวจต่อได้

## 2. การตัดสินใจที่ล็อกแล้ว (จากคำตอบพี่อาร์ต 12 ก.ย.)

| # | เรื่อง | ตัดสินใจ |
|---|---|---|
| 1 | ผู้ใช้หลัก | คนยิงแอด · พี่ทัชดู Overview |
| 2 | หน่วยหลัก | **แคมเปญของแพลตฟอร์ม** (Meta campaign ฯลฯ) · tag รวมเป็น "แคมเปญการตลาด" ทีหลัง (ไม่ทำรอบนี้) |
| 3 | ทางเข้า | เมนูใหม่ "แคมเปญ" (`/mkt/campaigns`) · ลิงก์จากการ์ดแพลตฟอร์มใน Overview = **เฟส 2 ต้องถามก่อน** (พี่อาร์ตห้ามแก้หน้าปัจจุบัน) |
| 4 | จังหวะงบ | ลงถึงระดับแคมเปญ — งบแคมเปญ (mock) = งบแพลตฟอร์ม × สัดส่วนของแคมเปญ |
| 5 | เกณฑ์ผลดี/แย่ | ใช้ `settings.ads_control.targets[brandId]` (`cpl` สูงสุด · `roas` ขั้นต่ำ) ที่หน้าตั้งค่าของ Codex มีแล้ว + `ACTION_RULES` เดิม |
| 6 | ยอดขายราย campaign | **ROAS attribution** (revenue ของการ์ดแคมเปญ ÷ spend) ติดป้าย "attribution" — ROAS ธุรกิจอยู่ระดับแบรนด์บน Overview เท่านั้น · เมื่อ CRM map ได้ค่อยเพิ่มคอลัมน์ "ยอดขายจริง" |
| 7 | สิทธิ์ | อ่านอย่างเดียว ไม่สั่งงานกลับแพลตฟอร์ม |
| 8 | ครีเอทีฟ | อยู่ในแถวขยายของแคมเปญ · แยกหน้าเมื่อมีข้อมูลจริง |
| 9 | มือถือ | Desktop-first · ≤900px ตารางกลายเป็นการ์ดซ้อน (ใช้งานได้ ไม่ต้องสวยเท่า desktop) |
| 10 | โครง | route ใหม่ + reuse toolbar/sidebar (CSS `aw-*`) ของ Overview · **ไม่แตะ `AdsView.jsx` / `AdsWorkspace.jsx`** |

## 4. ข้อมูล

**มีอยู่แล้ว (mock):** การ์ดรายวัน `ma_*` มี `campaign`, `creative`, metrics (spend · leads · revenue · impressions · clicks · reach) → รวมเป็นแคมเปญได้ · `ACTION_RULES`/`decideAction`/`adsCreativeRows` (Scale-Fix-Stop + fatigue) มีในโมเดล+เทสอยู่แล้ว

**เพิ่ม (mock — ตรงกับ `ad_daily_facts.level = 'campaign'` ที่จะมาจริง):**
- `campaign_budgets[]` = `{ brand_id, channel, campaign, month, share, objective, status }` — เก็บ **สัดส่วน** ไม่ใช่จำนวนเงิน เพื่อให้แก้งบแพลตฟอร์มที่หน้าตั้งค่าแล้วงบแคมเปญขยับตาม
- `DATA_VERSION` → `ssb-cp-v22`

**โมเดลใหม่ `src/modules/marketing/adsCampaigns.js` (pure + เทส):** `campaignRows` · `campaignDecision` · `SAVED_VIEWS`/`applyView` · `campaignTotals` · `sortCampaigns`

**ป้ายตัดสินใจ** (ทุกป้ายมี `why` + `next`):
| tag | ป้าย | เงื่อนไข (ตามลำดับ) |
|---|---|---|
| `wait` | รอข้อมูล | ข้อมูลไม่ครบ / น้อยกว่า 3 วัน / ลีด < 5 |
| `stop` | พิจารณาหยุด | `decideAction` = Stop (ใช้เงิน > wasteSpend ไม่มีผล · ROAS < stopRoas) |
| `fix` | ตรวจแก้ | fatigue · ROAS < fixRoas · CPL > highCpl · **CPL > เป้าแบรนด์ · ROAS < เป้าแบรนด์** |
| `gate` | ติด Gate | `decideAction` = Scale แต่งบแคมเปญเหลือ ≤ 0 หรือใช้เร็วกว่าจังหวะ |
| `scale` | พิจารณาสเกล | `decideAction` = Scale และไม่ติด Gate |
| `watch` | ติดตาม | ที่เหลือ |

## 5. ไม่ทำรอบนี้ (YAGNI)
เขียนกลับ API · breakdown (placement/device/geo) · tag แคมเปญการตลาด · หน้าครีเอทีฟแยก · ลิงก์จาก Overview (รอถาม) · Supabase migration (มีไฟล์ `0005` แล้ว ยังไม่ apply — ต้องถามตามกฎข้อ 3)

## 6. เกณฑ์ผ่าน
- โมเดลเทสเขียวทั้งหมด (เดิม 276 + ใหม่) · null ≠ 0 ทุกอัตราส่วน · ยอดรวมคิดจาก Σ ไม่เฉลี่ยรายแถว
- หน้าเปิดได้ที่ `/mkt/campaigns` เมนูโผล่ · Overview ไม่เปลี่ยนแม้พิกเซลเดียว (เทียบ screenshot ก่อน/หลัง)
- จอ 1500/2000: ไม่มี overflow · ≤900: แถวเป็นการ์ด · contrast ≥ 4.5:1 · ปุ่ม ≥ 24px · กราฟมีตารางสำรอง
