## สิ่งที่หน้าต้องตอบ (โจทย์ของฝ่ายบัญชี)

1. เดือนนี้ค่าแอดแต่ละบัญชี/แบรนด์เท่าไหร่ (ระบบนับ) + VAT 7% โดยประมาณ
2. **เงินออกนอกระบบ**: บัญชีแอดที่ token เห็น (8 บัญชี) แต่ไม่ได้เชื่อมเข้า dashboard (เชื่อม 4) มีการใช้เงินไหม เท่าไหร่
3. ยอดค้างที่ Meta ยังไม่ตัด (`balance`) + สถานะบัญชี (`account_status` ≠ 1 = มีปัญหา เสี่ยงแอดหยุด)
4. เทียบกับ statement บัตร: บัญชีกรอกยอดรวมเดือนที่เห็นจาก statement (ไม่บังคับ) → ระบบคำนวณส่วนต่าง + จัดสถานะ
5. เงินก้อนนี้ไปกับอะไร: ไส้ในต่อบัญชี → แคมเปญ (top + ที่เหลือรวม)
6. บันทึกผลตรวจ: append-only มีชื่อ+เวลา+หมายเหตุ แก้/ลบไม่ได้ · ใบสถานะปกติกดยืนยันได้ทีเดียว

## กติกาการแสดงผล (ภาษาเดียวกับหน้า Overview)

- ป้าย exception-based ตระกูล `paceFlag`: ปกติ = เงียบ · มีเรื่อง = ป้าย
- สถานะแถวรายเดือน (ต่อบัญชี): `match` ตรงกัน (|diff| ≤ 0.5%) · `minor` ต่างเล็กน้อย (≤ 2%) · `review` ต้องตรวจ (> 2%) · `nostatement` ยังไม่กรอก statement (โทนเทา ไม่ใช่คำเตือน) · `offsystem` บัญชีนอกระบบ (แดง)
- เกณฑ์ 0.5% / 2% ยึดตามเกณฑ์ Pace Engine เดิม อ่านจากค่าคงที่ในโมเดล (ยังไม่ทำหน้าตั้งค่า — YAGNI)
- ตัวเลขเงิน ทศนิยม 2 ตำแหน่ง · % ตัดทศนิยม 2 ตำแหน่ง **ไม่ปัด** (กติกา memory)
- VAT ทุกที่กำกับว่า "ค่าประมาณ (คำนวณ 7%)" — ไม่ใช่เอกสารทางการ
- UI mockup อ้างอิง: https://claude.ai/artifact/HMuqvWHExSxHW7AG4VhgQi (ปรับจากรายใบเป็นรายเดือน · คอลัมน์ "จ่าย (Meta)" → "ยอดค้างตอนนี้" · คอลัมน์ PDF → ลิงก์ Billing hub เดียวทั้งหน้า)

## แหล่งข้อมูล

| ข้อมูล | แหล่ง | ใหม่/มีแล้ว |
|---|---|---|
| ค่าแอดรายวัน/แคมเปญ ต่อ connection | `ad_daily_facts` ผ่าน `useAdsData` (cards) | มีแล้ว |
| บัญชีที่เชื่อม + brand | `ad_connections` | มีแล้ว |
| **snapshot บัญชีทั้งหมดที่ token เห็น**: `account_id, name, amount_spent, balance, account_status, currency` | Graph `GET /me/adaccounts` ด้วย token OAuth ที่เก็บใน `ad_oauth` (0007) — เก็บลงตาราง `ad_account_snapshots` โดย ads-cron รอบละครั้ง | **ใหม่** |
| ผลตรวจ + statement | ตาราง `ad_billing_reviews` (append-only) เขียนผ่าน RPC | **ใหม่** |
| ท่อเมล (เตรียม) | ตาราง `ad_billing_charges` — ว่างไว้ | **ใหม่ (โครง)** |

หมายเหตุ `amount_spent` ของ Graph เป็น **สตางค์สะสมตลอดชีพบัญชี** (minor units, lifetime) — ใช้ตรวจ "บัญชีนอกระบบมีการใช้เงิน" ด้วยส่วนต่างระหว่าง snapshot สองรอบ (`spentDelta`) ไม่ใช่ยอดเดือนตรงๆ · แสดงเป็น "ใช้เพิ่มในช่วง X วัน ≈ ฿Y"

## ความปลอดภัย / กติกาที่ห้ามพลาด

- ตารางใหม่ทั้ง 3: RLS เปิด · อ่าน/เขียนเฉพาะ team_lead ผ่าน `mkt_is_team_lead()` (มีแล้วจาก 0005) · `ad_billing_reviews` ห้ามมี UPDATE/DELETE policy (append-only จริงระดับ DB)
- ไม่มีข้อมูลลูกค้าในฟีเจอร์นี้ (ตัวเลขการเงิน+ชื่อแคมเปญเท่านั้น)
- repo public — ห้ามมี key/บัญชีจริงในโค้ดหรือเทส (fixture ใช้เลขสมมุติ)
- **ทุกการรัน migration / deploy function บน Supabase จริง ต้องขออนุมัติอาร์ตก่อนเป็นรายการ** (กฎข้อ 3) — งานในแผนเขียนไฟล์ให้ครบและเทสด้วย fixture ได้โดยไม่แตะฐานจริง
- git: commit ต่อ task ได้ แต่**ห้าม push** จนกว่าอาร์ตสั่ง
