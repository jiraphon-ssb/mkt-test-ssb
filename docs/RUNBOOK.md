# Runbook — ข้อมูลไม่เข้า หรือตัวเลขไม่ตรง ทำยังไง

> สำหรับทีม SSB · อัปเดต 17 ก.ย. 2569 · หน้าที่ใช้ตรวจคือ **สถานะ Sync** (`/mkt/ads/sync`)

## เริ่มที่บนสุดของหน้าสถานะ Sync

| ส่วน | บอกอะไร |
|---|---|
| **สรุปบนสุด** | ข้อมูลพร้อมใช้ · ใช้ได้แต่มีเรื่องควรดู · ต้องแก้ N เรื่อง · หรือ "กำลังตรวจข้อมูล…" ถ้ายังโหลดไม่เสร็จ (อย่าเพิ่งสรุปอะไรตอนนั้น) |
| **เรื่องที่ควรดู** | แบ่ง **ต้องแก้** · **เตือน** · **รอคนอื่น** แต่ละเรื่องมีปุ่มพาไปแก้ |
| **แหล่งข้อมูล** | แหล่งละแถว (ค่าแอด Meta · Creative · ยอดขาย TD/JD/TA · ยอดขาย JUNTAKARN) บอก สถานะ · สดแค่ไหน · ครบแค่ไหน |
| **แท็บรายละเอียด** | บัญชี Meta · ยอดขาย · สิทธิ์และคีย์ · ประวัติ (ลิงก์ตรงได้ เช่น `?tab=history`) |

ปุ่ม **ดึงข้อมูลตอนนี้** และเมนู **งานอื่น** (ตรวจยอดกับ Meta · ดึงยอดขาย · ดึงย้อนหลัง · ตรวจการเชื่อมต่อระบบขาย · สำรวจแหล่ง) เห็นเฉพาะหัวหน้าทีม

## 1. ตัวดึงอัตโนมัติยังวิ่งอยู่ไหม

ถ้าหยุด จะขึ้นในเรื่องที่ควรดูว่า **"ตัวดึงอัตโนมัติ: …"** · รายละเอียดดูแท็บ **ประวัติ** กรอง "รอบอัตโนมัติ"

| ป้าย | แปลว่า | ทำอะไร |
|---|---|---|
| เงียบเกินกำหนด | ไม่มีรอบเลยเกิน 2 ชั่วโมง | ตัวตั้งเวลาในฐานข้อมูลหยุด — ดูหัวข้อ "ตัวตั้งเวลาไม่ทำงาน" |
| รอบล่าสุดไม่สำเร็จ / ค้างกลางทาง | รอบล่าสุดพังหรือถูกตัดกลางคัน | ดูผลของรอบนั้นในแท็บประวัติ แล้วเทียบตารางในข้อ 2–3 |
| ยังไม่เริ่มทำงาน | ยังไม่เคยมีรอบเลย | ยังไม่ได้ตั้งค่า Vault (ดูท้ายไฟล์) |

รอบที่ไม่มีงานให้ทำไม่แสดงในประวัติ — ปกติจะเห็นงานจริงราว 4–5 ครั้งต่อวัน

## 2. ค่าแอด Meta ไม่เข้า

ดูแท็บ **บัญชี Meta** — บัญชีที่ต้องแก้อยู่บนสุด

| error ที่เห็น | แปลว่า | ทำอะไร |
|---|---|---|
| `META_TOKEN_EXPIRING` | การเชื่อม Meta ใกล้หมดอายุ (เตือนล่วงหน้า 7 วัน) | หน้าตั้งค่า → บัญชี → กดเชื่อม Meta ใหม่ ใช้เวลาไม่ถึงนาที |
| `META_TOKEN_INVALID` | หมดอายุแล้ว หรือถูกถอนสิทธิ์ | เชื่อมใหม่เหมือนกัน · ระหว่างนี้บัญชีนั้นถูกข้าม (บัญชีอื่นยังดึงตามปกติ) |
| `META_RATE_LIMIT` | Meta จำกัดปริมาณชั่วคราว | ไม่ต้องทำอะไร รอบถัดไปดึงต่อเอง |
| `SYNC_EMPTY_RESULT` | Meta ตอบว่าไม่มีข้อมูลทั้งที่เคยมี — ระบบไม่เขียนทับของเดิม | ถ้าขึ้นติดกันหลายวันให้แจ้งอาร์ต |
| `META_TOO_MUCH_DATA` | ช่วงวันที่ขอใหญ่เกินสำหรับบัญชีนั้น | กด "ดึงข้อมูลตอนนี้" เพื่อไล่ทีละก้อนเล็กลง |
| `AUTHORIZATION_NOT_READY` | คนที่เชื่อมบัญชีไว้ถูกปิดสิทธิ์/ออกจากทีม | หัวหน้าทีมเชื่อมบัญชีใหม่ |

"วันที่ขาด" มีตัวเลข = ระบบทยอยเติมเองชั่วโมงละ 4 ก้อน หรือกด **ดึงข้อมูลตอนนี้** ให้จบเร็วขึ้น

### วันหมดอายุของ token Meta

ระบบอ่านวันหมดอายุจริงจาก Meta (`/debug_token`) ตอนเชื่อมบัญชี และตอนดึงข้อมูลวันละครั้งต่อ token — ใช้วันที่มาก่อนระหว่าง "token หมดอายุ" กับ "สิทธิ์เข้าถึงข้อมูลหมดอายุ" (ราว 90 วัน) ดูได้ที่แท็บ **สิทธิ์และคีย์**

- **เหลือ N วัน** — ขึ้นเตือนเมื่อเหลือ ≤21 วัน และเป็นเรื่องต้องแก้เมื่อ ≤7 วัน
- **ไม่รู้วันหมดอายุ** — ยังไม่เคยอ่านได้ (เช่นเพิ่งอัปเดตระบบ) ระบบจะอ่านเองในรอบดึงถัดไป ถ้าขึ้นค้างเกิน 1 วันให้แจ้งอาร์ต
- ถ้า Meta ตอบว่า token ใช้ไม่ได้แล้ว บัญชีจะขึ้นหมดอายุทันทีและหยุดดึง — เชื่อมใหม่

## 3. ยอดขายไม่เข้า

ดูแถว **ยอดขาย TD · JD · TA** และแท็บ **ยอดขาย** · ระบบดึงเองวันละครั้งตี 5 ย้อนต้นเดือน อย่างน้อย 14 วัน (ทับของเดิม)

| error ที่เห็น | แปลว่า | ทำอะไร |
|---|---|---|
| `SALES_API_NOT_CONFIGURED` | ยังไม่ได้ตั้ง `SALES_API_URL` / `SALES_API_KEY` | ตั้งใน Supabase → Edge Functions → Secrets |
| `SALES_READ_FAILED` | อ่านจากระบบขายไม่ได้ (คีย์ผิด/ถูกถอน/ระบบขายล่ม) | เมนูงานอื่น → **ตรวจการเชื่อมต่อระบบขาย** · คีย์ถูกถอน = ขอคีย์ `marketing_bridge` ใหม่จากพี่ทัช |
| `SALES_EMPTY_RESULT` | ระบบขายตอบว่าไม่มีข้อมูลทั้งช่วง — ไม่เขียนทับของเดิม | ถ้าขึ้นติดกันให้ถามฝั่งระบบขาย |
| `SALES_COLUMN_LEAK` | ระบบขายส่งคอลัมน์เกินที่ขอ (อาจมีข้อมูลลูกค้า) — หยุดไว้ก่อน | แจ้งอาร์ตทันที อย่ากดดึงซ้ำ |
| `SALES_GOALS_FAILED` | ยอดเข้าแล้วแต่อ่านเป้าไม่ได้ | ยอดใช้ได้ปกติ · ลองดึงใหม่รอบหน้า |
| `SALES_RANGE_TOO_LONG` | สั่งดึงเกิน 93 วันในครั้งเดียว | ใช้ "ดึงยอดขายย้อนหลัง 3 เดือน" (แบ่งทีละเดือนให้เอง) |

สิ่งที่ **ไม่ใช่** ปัญหาของระบบเรา (แท็บยอดขาย → ความครบของข้อมูล)

- **ทีมยังไม่กรอก** (สีแดง) — ทีมขายไม่ได้กรอกคนทักวันนั้น ต้องไปกรอกในระบบขาย
- **เริ่มเก็บ 1 ก.ย.** (สีเทา) — ระบบขายเพิ่งเริ่มเก็บข้อมูลนั้น ก่อนหน้าไม่มีจริง
- **วันนี้ยังไม่ปิด** — ไม่นับเป็นวันที่ขาด
- **เป้าเดือนนี้ขึ้น —** — ยังไม่มีใครตั้งค่าในหน้าเป้าหมายของระบบขาย (งบแอด · CPL · ROAS · %Ads · CAC)

## 4. ยอดหรือเป้าของ JUNTAKARN ไม่เข้า

ดูแถว **ยอดขาย JUNTAKARN** ในหน้าสถานะ Sync · มาจากระบบ TMK คนละโปรเจกต์ Supabase — ดึงพร้อมรอบยอดขาย วันละครั้ง

| error ที่เห็น | แปลว่า | ทำอะไร |
|---|---|---|
| `JK_MISSING` / `JK_GOAL_MISSING` | โปรเจกต์ TMK ยังไม่มีฟังก์ชัน | รันไฟล์ `supabase/migrations/20260918-jk-ads-daily-facts.sql` หรือ `20260919-jk-ads-monthly-goal.sql` ใน SQL Editor ของ TMK |
| `JK_NO_PERMISSION` / `JK_GOAL_NO_PERMISSION` | คีย์เรียกฟังก์ชันไม่ได้ | `JK_API_KEY` ต้องเป็น service role key ของโปรเจกต์ TMK (ไม่ใช่ publishable) |
| `JK_BAD_KEY` · `JK_ERROR` | คีย์ผิด/หมดอายุ หรือ URL ผิด | ตรวจ `JK_API_URL` / `JK_API_KEY` ใน Edge Function Secrets |
| `JK_COLUMN_LEAK` / `JK_GOAL_COLUMN_LEAK` | ฝั่ง TMK ส่งคอลัมน์เกินที่ขอ — หยุดก่อนเขียน | แจ้งอาร์ตทันที อย่ากดดึงซ้ำ (มักแปลว่ามีคนแก้ RPC ฝั่งโน้น) |
| `JK_EMPTY_RESULT` | ได้วันไม่ครบทั้งช่วง — ไม่เขียนทับของเดิม | ลองดึงใหม่ ถ้ายังเหมือนเดิมให้ดู log ของ RPC ฝั่ง TMK |

**เป้าของ JUNTAKARN ขึ้น "ยังไม่ตั้งเป้า"** — ทีม TMK ต้องตั้งเป้าเดือนนั้นที่หน้า ตั้งค่า › เป้า & คอมมิชชั่น ของระบบ TMK ก่อน
(เรานับเฉพาะ เป้ายอดของช่อง **Facebook** · งบแอดนับเฉพาะ Facebook + Instagram = ค่าแอด Meta) · หรือตั้งเองที่ หน้าตั้งค่า › เป้า

## เป้าไม่ตรงกับที่ทีมตั้ง

เปิด **หน้าตั้งค่า › เป้า** แล้วดูป้ายใต้ช่องนั้น

- **จากระบบขาย / จากระบบ TMK** — ค่าที่ดึงมาตามปกติ แก้ที่ต้นทางแล้วรอบถัดไปจะตามมาเอง
- **ตั้งค่าเอง** — มีคนแก้ทับไว้ **ค่านี้ชนะเสมอ** แม้ต้นทางจะเปลี่ยนทีหลัง · กด **คืนค่า** ใต้ช่องเพื่อกลับไปใช้ค่าต้นทาง
- **ยังไม่ตั้ง** — ไม่มีทั้งค่าจากต้นทางและที่ตั้งเอง

เป้าแยกกันทีละเดือน — แก้เดือนนี้ไม่กระทบเดือนก่อน · ท่อ sync เขียนทับค่าที่คนแก้ไม่ได้ (คนละตาราง)

## ตัวเลขไม่ตรง

**ค่าแอดไม่ตรงกับ Ads Manager** — เมนูงานอื่น → **ตรวจยอดกับ Meta** เทียบ 7 และ 30 วัน (จบเมื่อวาน) ถ้าต่างเกินเกณฑ์ ให้ดูว่ามีวันที่ขาดไหม และตัวเลขที่ดูรวม "วันนี้" หรือเปล่า (Meta แก้ย้อนหลังได้ถึง 3 วัน)

**ยอดขายไม่ตรงกับแดชบอร์ดขาย** — ยอดขาย = ยืนยันออเดอร์ ณ วันจ่ายงวดแรก (นิยามเดียวกับแดชบอร์ดขาย · ยกเลิกแยกไว้ ไม่หักจากยอด) · ข้อมูลในหน้าเราอัปเดตวันละครั้ง ยอดที่เพิ่งยืนยันวันนี้อาจยังไม่เข้า

**ยอดขาย/ROAS ในหน้าแคมเปญต่างกับ Overview** — ระดับแคมเปญยังเป็นยอดที่ Meta เห็น (ติดป้าย "Meta เห็น") เพราะระบบขายยังไม่เก็บว่ายอดมาจากแคมเปญไหน · ระดับแบรนด์และภาพรวมใช้ยอดจริงจากระบบขาย

## ตัวตั้งเวลาไม่ทำงาน

ตรวจตามลำดับ (ต้องใช้สิทธิ์ Supabase)

```sql
-- 1. job ยังอยู่และเปิดอยู่ไหม
select jobname, schedule, active from cron.job where jobname = 'ads-sync-tick';

-- 2. ยิงทดสอบเดี๋ยวนั้น แล้วดูผล
select ads_ops.cron_tick();
select status_code, left(content, 300) from net._http_response order by id desc limit 1;

-- 3. ความลับใน Vault ยังอยู่ไหม (ไม่มี = tick จะข้ามเงียบๆ)
select name from vault.secrets where name in ('ads_cron_url', 'ads_cron_key');
```

ผลที่ควรได้จากข้อ 2 คือ `status_code = 200` และ content มี `"status":"success"`

## สั่งงานเองด้วย service key

ถ้าเรียก `sales-sync` หรือ `ads-creatives` เองด้วย service key (เช่นดึงย้อนหลังผ่าน `net.http_post` หรือ curl) ให้ส่ง `"trigger": "manual"` ใน body ด้วย ไม่งั้นแท็บประวัติจะขึ้นว่า "อัตโนมัติ" ทั้งที่มีคนสั่ง

## ค่าที่ต้องตั้งไว้ (ตั้งครั้งเดียว)

| ที่ไหน | ชื่อ | ใช้ทำอะไร |
|---|---|---|
| Supabase → Vault | `ads_cron_url`, `ads_cron_key` | ให้ pg_cron เรียก Edge Function ได้ |
| Supabase → Edge Functions → Secrets | `META_APP_ID`, `META_APP_SECRET`, `META_OAUTH_REDIRECT_URI`, `ADS_TOKEN_ENCRYPTION_KEY`, `ADS_APP_ORIGIN`, `ADS_ALLOWED_ORIGINS` | เชื่อม Meta · เข้ารหัส token · อ่านวันหมดอายุ token |
| Supabase → Edge Functions → Secrets | `SALES_API_URL`, `SALES_API_KEY` | ยอดขายจากระบบขาย — คีย์เป็น secret key ชื่อ `marketing_bridge` ในโปรเจกต์ของพี่ทัช (อ่านอย่างเดียว) |
| Vercel → Environment | `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY`, `VITE_AUTH_MODE=supabase` | ให้เว็บต่อฐานข้อมูลและบังคับล็อกอิน |
